name: complexity
description: コードの計算量を O 記法で解析・比較する。計算量・パフォーマンス比較を聞かれたとき、コミット間の計算量の変化を確認したいときに使う。
---

以下の手順でコードの計算量を解析して結果を表示してください。

## 引数パターン

- `{ファイルパス}` — 現在のコードを単体解析
- `{ファイルパス} {commitHash}` — 指定コミット時点のコードと現在のコードを**並列解析して比較**
- `{ファイルパス} {commitHash1} {commitHash2}` — 2つのコミットを比較。**解析前に `AskUserQuestion` で「どちらを Before にしますか？」と確認してから**解析する
- 引数なし — 直前に話題にしていたコードを対象にする

## 解析手順

### 単体解析の場合
1. 対象ファイルを読み込む
2. 各関数・メソッドについて時間計算量・空間計算量をビッグオー記法で解析する
3. ボトルネックを特定する

### 比較解析の場合（ファイル + コミット1つ）
1. `git show {commitHash}:{ファイルパス}` で指定コミット時点のコードを取得する
2. 現在のファイルを読み込む
3. 両バージョンそれぞれについて同じ解析を行う
4. 比較結果を出力する

### 比較解析の場合（コミット2つ）
1. `AskUserQuestion` で「{commitHash1} と {commitHash2} のどちらを Before にしますか？」と質問して回答を待つ
2. `git show {Before hash}:{ファイルパス}` と `git show {After hash}:{ファイルパス}` でそれぞれ取得する
3. 両バージョンそれぞれについて同じ解析を行う
4. 比較結果を出力する

## 出力フォーマット

**厳守事項: 出力は毎回完全に同じ構造・順序・表記で出力すること。**
- 関数の列挙順は必ずファイル内の出現順（行番号昇順）とする
- 計算量の表記は `O(1)`, `O(log n)`, `O(n)`, `O(n log n)`, `O(n²)`, `O(n³)`, `O(2^n)` のいずれかを使用する（独自表記禁止）
- 平均と最悪が異なる場合は `平均:O(?) / 最悪:O(?)` の形式で統一する
- 解析不能な箇所は `O(?)` と表記する
- セクション名・列名・記号は下記テンプレートから一切変更しない

### 単体解析の出力

```
## 計算量解析レポート: {ファイルパス}

| 関数/メソッド | 行 | 時間計算量 | 空間計算量 |
|-------------|-----|-----------|-----------|
| funcA       | 12  | O(n²)     | O(n)      |
| funcB       | 34  | O(log n)  | O(1)      |

### 根拠

| 関数/メソッド | 対象行 | 根拠 |
|-------------|--------|------|
| funcA       | 15-20  | ネストされた2重ループ |
| funcB       | 35-42  | 二分探索パターン |

### サマリー
- 最悪計算量: O(?) ([関数名] が支配的)
- ボトルネック:
  - [関数名] (行 XX): O(?) — 理由
  - [関数名] (行 YY): O(?) — 理由
```

### 比較解析の出力

```
## 計算量比較レポート: {ファイルパス}
- Before: {commitHash} ({コミットメッセージ1行})
- After:  現在 (HEAD)

## 変数定義

| 変数 | 意味 | 実測値 |
|------|------|--------|
| n    | ...  | —      |

※ 実測値が不明な場合は「—」とする

| 関数/メソッド | 時間 Before (DB) | 時間 Before (Python) | 時間 After (DB) | 時間 After (Python) | 空間 (Before) | 空間 (After) | 改善 |
|-------------|----------------|-------------------|----------------|-------------------|--------------|-------------|------|
| funcA       | O(n²)          | O(n)              | O(n log n)     | O(n)              | O(n)         | O(n)        | ✓    |
| funcB       | O(1)           | O(log n)          | O(1)           | O(log n)          | O(1)         | O(1)        | —    |

※ DBアクセスがない関数は DB 列を O(1) とする
※ 改善列: ✓=改善, ✗=悪化, —=変化なし

**Before 合計**: DB O(?), Python O(?) → 実数値 O(?)
**After  合計**: DB O(?), Python O(?) → 実数値 O(?)

※ 実測値が不明な場合は「実数値 O(?)」とする

### 根拠

| 関数/メソッド | Before 根拠 | After 根拠 |
|-------------|------------|-----------|
| funcA       | ネストされた2重ループ (行15-20) | マージソートに置換 (行15-18) |
| funcB       | 二分探索パターン (行35-42) | 変更なし |

### サマリー
- Before 最悪計算量: O(?) ([関数名] が支配的)
- After  最悪計算量: O(?) ([関数名] が支配的)
- 全体評価: [改善 / 悪化 / 変化なし]
- ボトルネック (After):
  - [関数名] (行 XX): O(?) — 理由
```

## 注意事項
- 日本語で出力する
- セクションの追加・削除・並び替えは行わない
- 表の列の追加・削除・並び替えは行わない
- 比較時、Before に存在して After に存在しない関数は `(削除)` と表記する
- 比較時、After に新規追加された関数は `(新規)` と表記する
