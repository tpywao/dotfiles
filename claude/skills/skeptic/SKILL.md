# 敵対的検証（skeptic）

成果物の主張・前提・結論を、生成の経緯を知らない独立したサブエージェントに「反証」させる。引数: "$ARGUMENTS"

## 原則

- **目的は反証**: レビューや改善提案ではない。成立しない可能性のある箇所だけを探す
- **独立性の担保**: 検証はサブエージェントが行う。成果物を作った本人（メインセッション）は検証に関与しない
- **結果は無加工**: skeptic の報告を改変・フィルタ・弁護なしで提示する

## 実行手順

### 1. 対象の特定

- 引数にファイルパスがあればそのファイルを対象にする
- 引数がなければ、直前の会話で生成・提示した成果物を対象にする
- 対象が一意に特定できない場合はユーザーに確認する

### 2. 成果物のファイル化

- 会話中の成果物はスクラッチパッドのファイルに**全文そのまま**保存する（要約・編集・整形をしない）
- ファイルパス指定の場合はそのファイルをそのまま使う
- PR が対象の場合は、`gh pr view --json` のメタデータと `gh pr diff` の全文を 1 ファイルに保存する

### 3. skeptic エージェントへ dispatch

`skeptic` サブエージェント（`~/.claude/agents/skeptic.md`）に以下のプロンプトを渡して実行する。反証のルール・裏取り手段・出力形式はエージェント定義に固定済みのため、呼び出し前のユーザー承認は不要（即 dispatch してよい）。`skeptic` エージェントが利用できない環境では `general-purpose` で代替し、エージェント定義の本文をプロンプトに含める。

**独立性を壊さないこと**: プロンプトに成果物ファイルのパス以外の文脈（生成の意図、会話の経緯、「〜のために作った」等の補足）を一切加えない。

```
以下のファイルに保存された成果物を検証してください:

<対象ファイルの絶対パス>

指摘が 4 件以上になりそうな場合は、エージェント定義の「随時報告」に従い、指摘 2〜3 件を裏取りした時点で残りに着手せずターンを終えて部分報告してください。続行指示はこちらから送ります。

回答・報告はすべて日本語で書くこと。技術用語やコード識別子は原文のままでよい。
```

### 4. 結果の提示

- skeptic の報告を**全文そのまま**提示する
- 各指摘への反論・弁護・妥当性のトリアージをしない。作った本人が選別すると独立検証の意味がなくなる
- 対応要否の判断はユーザーに委ねる。ユーザーが対応を指示した場合のみ修正に着手する
- 指摘をファイルに残したい場合は、skeptic に書かせずメインセッションが報告を無加工でファイル化する（skeptic は完全読み取り専用を維持する）

### 5. 報告の軽量再検証

skeptic の報告自体の事実主張を、2体目の独立エージェントにざっくり照合させる（報告内の引用・参照が実在するかの確認であり、2回目の反証ではない）。

**随時報告との並行実行**: skeptic は指摘が確定するごとに部分報告してターンを終える（エージェント定義の「随時報告」）。部分報告が届いたら、(1) その部分をファイル化して下記の再検証を dispatch し、(2) skeptic へ SendMessage で続行を指示する——の 2 つを同時に行う。これで検証と照合がオーバーラップする。部分報告は中間成果物なのでユーザーへの全文提示は最終報告（完全版）だけでよいが、深刻度 高 の指摘は届いた時点で共有する。

- skeptic の報告（部分報告ならその全文）を、**通知テキストの転記ではなく** skeptic の transcript（Agent 呼び出し結果の output_file）から機械抽出してスクラッチパッドの新しいファイルに保存する。通知経由の転記はハーネスのエスケープ（`>=` → `&gt;=` 等）やモデル再出力による劣化が入り、出力トークンも報告全文分かかるため使わない:

  ```bash
  jq -rs '[.[] | select(.type=="assistant")] | last | .message.content | map(select(.type=="text") | .text) | join("\n")' <output_file> > <保存先ファイル>
  ```

  抽出後は `wc -c` と報告固有の文字列の `grep -c` で中身を確認する（`cat` で全文をコンテキストに載せない）
- `skeptic` サブエージェント（利用不可なら `general-purpose`）に以下のプロンプトを渡して dispatch する。プロンプトは固定のため、呼び出し前のユーザー承認は不要

```
以下のファイルは成果物への反証レビュー報告です。報告内の事実主張（参照されたファイルパス・行番号・コマンド・URL・数値）が実在し整合するかをざっくり照合してください。新しい指摘の追加や深掘りはせず、各指摘について「照合OK / 矛盾あり（内容）/ 未照合」のみを列挙してください。

<報告ファイルの絶対パス>

回答・報告はすべて日本語で書くこと。技術用語やコード識別子は原文のままでよい。
```

- 再検証の結果も無加工で提示する。「矛盾あり」となった指摘もメインセッションは取り下げず、その旨を添えてユーザーの判断材料にする

## 注意事項

- 報告を要約して「概ね問題なし」等に丸めない。深刻度・確度はユーザーが読んで判断する
- skeptic が「未検証」とした事実主張を、メインセッションが記憶で補って「検証済み」扱いにしない
- 成果物を修正した後に再検証する場合は、修正版を新しいファイルに保存して手順を最初からやり直す（前回の指摘をプロンプトに含めない）
