Backlog にチケットを起票する。

引数 `$ARGUMENTS` には参考にする md ファイルパス、既存チケット番号、または起票内容の自由記述が渡される。引数なしなら `AskUserQuestion` で起票元（既存 md / 直近の調査結果 / 自由記述）を確認する。

## 手順

### 1. 元ネタ取得

- md ファイルパスが渡されたら Read で読む
- チケット番号 (例 `PROJ-1234`) なら `mcp__backlog__get_issue` で取得して参照する
- 自由記述ならそのまま使う

### 2. ドラフト作成

- タイトル（簡潔・命令形）
- 本文（マークダウン）
- 含めない項目は事前に `AskUserQuestion` で確認: 背景 / 影響範囲 / 再現手順 / 関連調査
- 過去パターンでは「背景・影響範囲は不要、関連チケットへの参照のみ」というケースあり

### 3. プロジェクト・カテゴリ確認

- プロジェクトキーは `AskUserQuestion` で確認（例: `PROJ`）
- 必要なら `mcp__backlog__get_custom_fields` でカスタムフィールド一覧を取得
- 担当者・優先度・カテゴリは指定がない限り未設定で起票

### 4. プレビューと確認

- タイトル + 本文をユーザに提示し起票してよいか確認する
- 修正指示があれば反映して再プレビュー

### 5. 起票

- `mcp__backlog__add_issue` で起票
- 戻り値からチケット ID と URL を取り出して表示する

## 注意事項

- 起票は副作用ありの操作なのでプレビューなしに実行しない
- タイトルや本文に「TODO」「あとで」など曖昧な語を残さない
- 日本語で出力する
