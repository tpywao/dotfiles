# claude-learn: 会話からのナレッジ更新・スキル化を促す仕組み

- 日付: 2026-07-17
- 対象リポジトリ: `~/.dotfiles`（Claude Code 設定を管理）

## 目的

Claude Code との会話の中で得られた「今後に残す価値のある学び」を、適切なタイミングで
確実に **ナレッジ（メモリ / CLAUDE.md）へ反映** し、必要なら **スキルとして作成・改善** する。

保存先（`memory/` + `MEMORY.md`、グローバル/プロジェクトの `CLAUDE.md`、`claude/skills/`）と
作り方（superpowers の `writing-skills`）は既に揃っている。本仕組みが埋めるのは、その手前の
**「今これを残すべき / スキル化すべき」という判断と着手を、会話の流れの中で起こすトリガー**である。

## 設計方針

### スキル中心（フックもサブエージェントも使わない）

2つの設計軸で検討した結果、**メインセッションで動く単一スキル + CLAUDE.md の一文**に落ち着いた。

**トリガー軸**（誰が起動するか）:
- フックは Claude のエージェントループ外で動くシェルコマンドで、Agent/Task ツールを呼べない。よって
  「フックがサブエージェントを起動」は綺麗なプリミティブとして存在しない。現実的実装は (a) 指示を
  コンテキスト注入して Claude に判断させる（＝確率的で CLAUDE.md 一文と等価、かつ前回会話のキーワード
  走査版はノイズが多い）か、(b) `claude -p` headless を shell out（重く、人間不在で共有ファイルに自動
  書き込みするリスク大）のどちらか。いずれも割に合わない。
- よって能動トリガーは **CLAUDE.md の一文**が最良。会話の中にいて全文脈を持つ Claude が意味的に判断でき、
  恒久指示の置き場所としても正しい。

**実行者軸**（誰が会話を読む→分類→書き込むか）:
- メインセッションは会話を既にコンテキストに持っている。サブエージェントは独立コンテキストなので
  同じ会話を transcript.jsonl から読み直すしかなく、無料で持っている情報をトークンを払って劣化取得する
  ことになる。情報の非対称性はメインセッションが有利。
- サブエージェントはユーザーと対話できない（AskUserQuestion の往復不可）。この仕事の肝である「保存前の
  人間確認」——特に共有ファイル CLAUDE.md への書き込み——をサブエージェント内に置けない。
- 文脈衛生（メイン文脈を汚さない）というサブエージェントの一般的利点は、ここでは上記の情報優位に負ける。

留保: 会話が巨大でメイン文脈が逼迫する場合に限り、**抽出フェーズだけ**サブエージェントに逃がす価値はある
（確認・書き込みは必ずメインに戻す）。将来の最適化として YAGNI で今は入れない。

### 精度向上の補強策（スキル側に集約）

1. **重複除外**: 既存の `MEMORY.md` / 両 `CLAUDE.md` / `skills/` と突合し、既出は候補から外す。採用済みは
   実体が履歴を兼ねるため専用の採用履歴は持たない。
2. **却下履歴突合**: 過去にユーザーが「残さない」と判断した候補は再提案しない。

## コンポーネント

### A. 手動スキル `claude/skills/claude-learn/SKILL.md`（新規・単一ディスパッチャ）

- 起動トリガー（description）: 「会話で得た学びをメモリ / CLAUDE.md / スキルに反映したいとき。
  会話で恒久的な学び・フィードバックが出て保存を検討したいとき。」
- 手順:
  1. 現在の transcript を読み、残す価値のある学びを候補として抽出。
  2. 各候補を分類:
     - **メモリ** (`memory/` + `MEMORY.md`): 会話をまたいで効く事実。既存メモリ運用ルール（frontmatter、
       `type`、`MEMORY.md` へ1行追記）に従う。
     - **CLAUDE.md**: 恒久的な作業規則。グローバル `~/.claude/CLAUDE.md` かプロジェクト
       `.dotfiles/claude/CLAUDE.md` かを内容で判断（プロジェクト CLAUDE.md は共有物なので追記は慎重に）。
     - **スキル化**: 手順化できる反復作業。`superpowers:writing-skills` を呼ぶ。既存スキル改善もここ。
  3. **重複除外**: 既存の `MEMORY.md` / 両 `CLAUDE.md` / `skills/` と突合し、既出は落とす。
  4. **却下履歴突合**: 却下履歴ファイル（B）を読み、意味的に一致する候補は提案しない。
  5. 分類結果をユーザーに提示し、採否を確認（AskUserQuestion）。
  6. 採用分を各フローへ振り分けて反映。
  7. **却下分**を却下履歴に1行正規化して追記（日付 + 1行サマリ）。
- CLAUDE.md のグローバル指示に従い、質問は AskUserQuestion を使う。

### B. 却下履歴ファイル `~/.claude/learn-candidates/<cwd-slug>.md`

- マシンローカル（dotfiles / git 管理外、hardlink 同期対象外）。cwd-slug 単位。
- 人間可読の Markdown 追記（機械突合しないため JSON 不要）。1行 = `- YYYY-MM-DD: <1行サマリ>`。
- `claude-learn` スキルのみが読み書きする。ディレクトリが無ければスキルが mkdir -p。

### C. 能動トリガー = CLAUDE.md の一文（追記）

- グローバル `~/.claude/CLAUDE.md`（= `claude/CLAUDE.md`）に、恒久的な学び・フィードバックが会話で出たら
  `claude-learn` の実行を提案する旨を一文追記する。
- これにより「実行忘れ」を、フックではなく Claude の意味的判断で埋める。

## データフロー

    [会話中に恒久的な学び / フィードバックが出る]
      Claude が CLAUDE.md の指示に従い claude-learn の実行を提案（能動トリガー）
        ├─ もしくはユーザーが任意のタイミングで /claude-learn を起動
        ▼
      claude-learn スキル（メインセッション）
        ├─ transcript を精読して候補抽出
        ├─ メモリ / CLAUDE.md / スキル化 に分類
        ├─ 既存実体と突合し重複除外
        ├─ 却下履歴と意味的突合し既却下除外
        ├─ 採否を AskUserQuestion で確認
        ├─ 採用分を各フローへ反映
        └─ 却下分を却下履歴に追記

## dotfiles 統合上の注意

- `claude-learn/` は `claude/skills/` 配下に置き、既存 PostToolUse relink で `~/.claude/` に hardlink 同期される。
- CLAUDE.md の一文追記は `claude/CLAUDE.md`（グローバル）に対して行う。
- 却下履歴 `~/.claude/learn-candidates/` は git 管理外（dotfiles に含めない）。

## やらないこと（YAGNI）

- **フック全般**（SessionStart 検知・状態ファイル・前回 jsonl 走査）。能動トリガーは CLAUDE.md の一文で代替。
- **サブエージェント**（会話が既にメイン文脈にあり、人間確認も要るためメインスキルが適切）。
- 採用履歴ファイル（実体が履歴を兼ねる）。

## テスト観点

- `claude-learn` が3分類（メモリ / CLAUDE.md / スキル化）へ正しく振り分けるか。
- 既存 `MEMORY.md` と重複する候補を落とすか。
- 却下 → 次回同一候補が再提案されないか。
- CLAUDE.md の一文により、恒久的な学びが出た会話で実行提案がなされるか。
