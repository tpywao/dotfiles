# agent-status: エージェントの作業状態を Claude Sheets で共有する

- 日付: 2026-11-24
- 対象リポジトリ: `~/.dotfiles`（Claude Code 設定を管理）

## 目的

手元の各マシンで動く Claude Code のセッションが、いまどの作業をどんな状態で進めているかを、Claude Sheets の 1 つのシートにまとめる。人も、クラウドの Claude も、そのシートを読めば次のことが分かるようにする。

- どこに何が残っているか（未 push のコミット、PR 待ち、ユーザーの返答待ち）
- どれが止まっているか（落ちたセッション、放置された作業）

今の問題は、未 push のコミットや途中の作業が手元の worktree にしか無いこと。別のセッションからも GitHub からも見えず、途中で止まった作業が埋もれる。

最初に考えたのは「コミットしたら自動で push する」案だった。しかし push は外部への公開で、誤ってコミットした機密情報も確認なしに出ていくため採らない。コードは外に出さず、作業の**状態**だけを、組織の claude.ai アカウントの中にある非公開のシートへ書く。

## ゴール・非ゴール・アンチゴール

ゴール:

- ローカルのセッションが、ターンの終わりに自分の作業の状態をシートへ記録する
- ブランチを切る作業も、切らない作業（調査・質問・レビュー）も載る
- 完了した作業は active から deactivated へ移り、active には今の作業だけが残る
- 長く更新の無い作業が「放置」として見分けられる。落ちたセッションか、返答を待ったまま止まっている生きたセッションかまでは見分けない（記録の機会がターンの終わりだけなので、両者はシートからは同じに見える）

非ゴール:

- クラウドのセッション自身の状態の記録（クラウドの Claude は読む側）
- 作業の途中経過の履歴（残すのは作業ごとの最後の状態だけ）
- push・PR 作成の自動化

アンチゴール（動いても失敗とみなすもの）:

- コードやコミットの中身（diff）がシートや外部へ出る
- あるセッションの書き込みが、他のセッションの作業中の行を壊す・消す
- 記録のせいでターンを終えられなくなる、または毎ターン目に見えて遅くなる
- シートの URL など、アカウント固有の値がこのリポジトリに入る（固有文言の禁止）

## 制約

- **Claude Sheets はモデルしか書けない。** 読み書きは Claude Docs コネクタ（MCP）経由だけで、hook（シェル）からは書けない。hook にできるのは、記録に必要な値を集めてモデルに渡し、書くよう促すところまで
- **版の検査はワークブック単位。** 更新には `base`（最後に見た版）が要り、誰かがワークブックのどこかを編集していれば `baseIsNotTheRevision` で拒否される。1 回の `applyEdits` はアトミック（全部通るか、何も通らない）
- **Stop hook でターンを続けさせる経路**: `hookSpecificOutput.additionalContext` を返すと、エラー扱いされずに会話が続く（公式の hooks reference で確認）。`stop_hook_active` が true のターン終わりでは何も返さない。こうして続けさせるのは 1 回に限り、ターンを終えられなくなることを防ぐ
- 記録してよい範囲（ユーザーが決めた）: リポジトリ名・ブランチ・未 push 件数・コミット件名・作業メモ
- このリポジトリの規約に従う: hook のテストは `tests/claude/`、`claude/settings.json` は `merge_config` で配布される

## 検討した方式

| 方式 | 中身 | 採否 |
| --- | --- | --- |
| Active table 型（採用） | active と deactivated の 2 枚。1 行 1 作業で、自分の行を更新し、完了したら行を deactivated へ移す | 採用。未確認の部品が無い（`readCells` / `writeCells` / `deleteRows` だけ）。行の移動を 1 回の `applyEdits` にしてアトミックにできる。active が常に小さい |
| View 型 | イベントのログへ追記するだけにし、最新の状態は数式（SQL の View 相当）で出す | 不採用。追記だけなので他の行を壊さず、履歴も残る。しかし `FILTER` / `UNIQUE` / スピルが Claude Sheets にあるか未確認で、ログが 500,000 セルの上限へ向かって増え、刈る仕組みも要る |
| GitHub Issues（hook が `gh` で書く） | 1 作業 1 Issue | 不採用。hook が直接書けるのでモデルに依存しないが、勤務先の作業内容が個人の GitHub アカウントへ出る |
| Remote Control のみ | claude.ai/code のセッション一覧で見る | 単独では不採用。見えるのは接続中のセッションと会話だけで、ブランチや未 push のコミットは出ない。シートの行から該当するセッションを辿る補助として使う |
| 自動 push（当初案） | コミットしたら push する | 不採用。機密情報を確認なしに外へ出す |

## 決定事項

### シートの構成

既存の Claude Sheets を 1 つ使う。URL はリポジトリに書かず、各マシンのローカルの設定から読む（後述）。

**`active` シート**: 1 行目がヘッダ、2 行目から 1 行 1 作業。

| 列 | 中身 | 書く人 |
| --- | --- | --- |
| リポジトリ | origin の `owner/repo`。origin が無い、または git の外なら cwd のディレクトリ名 | hook が値を渡す |
| ブランチ | 作業ブランチ。ブランチを切らない作業は空（判定は下の「ブランチを切らない作業の判定」） | hook |
| 状態 | ドロップダウン: 作業中 / ユーザー待ち / PR 待ち / 完了 / 放置 | モデル |
| 作業メモ | 何をしていて、次に何が要るか。1〜2 文 | モデル |
| 未 push 件数 | どのリモートブランチにも無いコミットの件数 | hook |
| 最新コミット件名 | HEAD の件名。未 push のときだけ | hook |
| PR | PR の URL（あれば） | モデル |
| マシン | ホスト名 | hook |
| セッション ID | 最後に更新したセッションの `session_id` | hook |
| 最終更新 | 日本時間の日時 | hook（時刻）を元にモデルが書く |

**`deactivated` シート**: `active` と同じ列に「移動日時」を足す。新しいものを下に追記する。

**`設定` シート**: 設定値は作業の表と混ぜず、このシートにまとめる。A 列に項目名、B 列に値を置き、記録するセッションは毎回ここを読む（コードやスキルに値を書き込まない）。最初に置く値は次の 2 つ。

| 項目 | 値 |
| --- | --- |
| 完了から deactivated へ移すまで（時間） | 24 |
| 更新が無いまま放置とするまで（時間） | 72 |

設定値を増やすときもこのシートに行を足す。

### ブランチを切らない作業の判定

次のどれかに当たるとき、hook はブランチ列を空にする。行はセッション ID で探すことになる。

- origin のデフォルトブランチ（`refs/remotes/origin/HEAD` が指すもの）にいる
- detached HEAD
- worktree ではなく、メインの作業ツリーにいる（`git rev-parse --path-format=absolute --git-dir --git-common-dir` の 2 行が同じ）
  - `--path-format=absolute` を付けずに比べてはいけない。cwd がサブディレクトリのとき、片方が絶対パス、もう片方が相対パスで返り、メインの作業ツリーでも一致しなくなる

ベースブランチ上の調査や質問を「リポジトリ + ブランチ」で探すと、同じリポジトリのメインの作業ツリーで動く複数のセッションが 1 行を奪い合う。ベースブランチの名前はリポジトリによって違い（ユーザーに確認した）、デフォルトブランチとは別のブランチを起点にするリポジトリもあるため、デフォルトブランチだけでは判定できない。そこで、コミットする作業は worktree で行うという運用（グローバル指示）に合わせて、メインの作業ツリーも空にする。

### 自分の行の探し方

1. ブランチがあれば、リポジトリ + ブランチが一致する行。別のセッションが同じブランチで再開しても、同じ行を更新する
2. 無ければ、セッション ID が一致し、かつブランチ列が空の行。ブランチを切らない作業はこちらで見つかる。複数あれば最終更新が新しい行を使う。調査から始めて途中でブランチを切った作業は、この行にブランチを書き足して続ける（以降は 1 で見つかる）
3. どちらでも無ければ、末尾に新しい行を足す

ここでいうブランチは hook が渡す値で、cwd から決まる。ただし、マージ後の片付けでブランチの作業を「完了」にするときは例外で、hook の値ではなく片付けたブランチの名前で 1 の行を探す（「完了と回収」）。

自分の行を見つけた読み取りの `revision` を、そのまま更新の `base` に渡す。拒否されたら読み直して 1 からやり直す。行番号がずれたまま書くことは、版の検査が防ぐ。

### 完了と回収

- **ブランチがある作業**: PR がマージされたら完了。マージ後の片付け（worktree とブランチの削除）をするセッションが、状態を「完了」にする
  - 片付けるセッションは worktree を出てメインの作業ツリーにいるので、hook が渡すブランチは空になる。また、作業したセッションとは別のセッションで片付けることも多く、セッション ID でも元の行に当たらない。そこで、片付けたブランチの名前（リポジトリ + ブランチ）で行を探して「完了」にする。見つからなければ何もしない（新しい行は足さない）
  - Claude で片付けをせず GitHub 上でマージだけした作業は、「PR 待ち」のまま active に残る。これは自動では片付けず、人が消す（ユーザーが決めた）。レビュー待ちで数日止まる PR は普通にあり、時間だけで「放置」にすると誤解を招く。スキルと `claude/README.md` にこの前提を書く
- **ブランチを切らない作業**: 依頼に答え終えたとモデルが判断したターンで「完了」にする。会話が続けば「作業中」へ戻す
- **回収は記録するセッションがついでに行う。** active と設定シートを読んだときに、「完了」から設定の時間（初期値 24 時間）以上たった行を見つけたら、自分の行の更新と同じ `applyEdits` で deactivated へ移す（追記 + `deleteRows`）。定期実行の部品は作らない
  - 編集は前の編集の結果に対して順に適用される。行を消すと下の行の番号が変わるため、自分の行を先に書き、消す行は下から順に並べる
  - **自分の行は回収の対象から外す。** 「完了」にした作業を翌日以降に再開すると、自分の行が回収の条件にも当たる。外さないと、「作業中」へ書き換えた行を同じ `applyEdits` の中で deactivated へ移して消してしまう
- **他のセッションの行に触れるのは 2 つの場合だけ**:
  - 「完了」から設定の時間以上たった行を移す
  - 「作業中」「ユーザー待ち」のまま設定の時間更新が無い行の状態を「放置」に変える。この行は移さず、消すかどうかは人が決める
- 「放置」は、落ちたセッションと、返答を待ったまま止まっている生きたセッションを区別しない。待っているあいだはターンが無く、記録の機会が無いため。そのセッションで会話が再開すれば、次の記録で元の状態に戻る
- 回収と「放置」への変更は、どれかのセッションが記録したときにしか起きない。誰も記録しないあいだは、シートの状態が古いまま残る。読む人（クラウドの Claude を含む）は、状態と合わせて最終更新も見る。スキルと `claude/README.md` にこの読み方を書く

### Stop hook（`claude/hooks/agent-status.sh`）

- stdin から `session_id`・`cwd`・`stop_hook_active` を読む。`stop_hook_active` が true なら何もしない
- シートの URL をローカルの設定（`${XDG_CONFIG_HOME:-~/.config}/dotfiles/agent-status-sheet`）から読む。無ければ黙って終わる。設定していないマシンでは何も起きない
- git から、リポジトリ・ブランチ・未 push 件数・最新コミット件名を集め、ホスト名・日本時間の現在時刻と合わせて `additionalContext` に載せる。シートへの書き方は載せず、スキルを名指しする
- **毎ターンは促さない。** セッションごとに、前回促したときの指紋（ブランチ・HEAD・未 push 件数）を `${XDG_STATE_HOME:-~/.local/state}/dotfiles/agent-status/<session_id>` に残す。促すのは次のどれかに当てはまるときだけ
  - そのセッションで初めてのターン終わり
  - 指紋が変わった
  - 前回促してから 30 分以上たった
- どの経路でも exit 0 で終わる。git・jq が無い、cwd が無いなどの場合も黙って通す

### スキル（`claude/skills/agent-status/SKILL.md`）

シートの読み書きの手順をここに置く。内容は次のとおり。

- Docs コネクタの `topic.sheets` を読んでから呼ぶ
- 行の探し方（マージ後の片付けでは、片付けたブランチの名前で探す）
- 更新の作り方（自分の行 + 回収を 1 つの `applyEdits` にまとめる。自分の行は回収の対象から外す）
- `baseIsNotTheRevision` での再試行
- 状態の選び方
- 作業メモの書き方（コミットの中身や diff は書かない）

hook のメッセージと、グローバル指示から参照する。

### グローバル指示（`claude/CLAUDE.md`）

短い節を足す。

- 作業の状態が変わったら（完了・ユーザー待ちになった・PR を出したなど）、ターンを終える前に `agent-status` スキルで記録する。hook の合図を待たない
- マージ後の片付けで worktree とブランチを消したら、片付けたブランチの行を「完了」にする。既存の「マージ後の後片付け」の節の手順にもこの一歩を足す
- push はユーザーが指示したときだけ。この仕組みは push の代わりではない

`claude/CLAUDE.md` を変更する PR #180 は 2026-11-24 にマージされた。実装はそのマージを含む main を起点にする。

## 前提の確認（実装の最初に行う）

次の 3 つが崩れると設計が成り立たないため、本実装の前に確かめる。

1. **クラウドの Claude セッションが、このシートを Docs コネクタで読めるか。** 読めなければ目的の半分が成り立たない
2. **Stop hook の `additionalContext` で続いたターンの中で、モデルが MCP ツールを呼んでシートへ書けるか**
3. **1 回の記録にかかる時間とツール呼び出しの回数**（`readSheets` → `readCells` → `applyEdits` の 3 回前後を想定）。アンチゴールの「目に見えて遅くなる」に当たらないか

## 実装する人に任せること

- hook の指紋の保存形式と、古い状態ファイルの掃除
- スキルの文面と、作業メモの例
- テストの組み方。hook は `tests/claude/agent-status_test.sh` で、促す経路・黙る経路（設定なし・`stop_hook_active`・指紋が同じで 30 分以内・git の外）・常に exit 0 をケースにする。ブランチ列の値（作業ブランチ・デフォルトブランチ・detached HEAD・メインの作業ツリーのルート・メインの作業ツリーのサブディレクトリ・worktree のサブディレクトリ）もケースにする。シートへの書き込みは使い捨てのシートで手で確かめる
- `AGENTS.md` へのテスト実行の追記と、`claude/README.md` の hook 一覧の更新

## 片付け

先行の PR #173（自動 push の規則と hook）は、この設計に置き換えるため 2026-11-24 に閉じた。ブランチ `feat/claude-push-after-commit`（ローカル・リモートとも）と、その worktree も同日に消した。実装で片付けるものは残っていない。

- その worktree に残っていた未コミットの変更（push させずに報告だけさせる版への書き換え）も、ユーザーの承認を得て捨てた。未 push の状態はこの設計の「未 push 件数」列で見えるようになる
- ローカルのブランチは、リモートのブランチを消す前に `git branch -d` で消した。push 済みで upstream と一致していたので、upstream の判定で通った
